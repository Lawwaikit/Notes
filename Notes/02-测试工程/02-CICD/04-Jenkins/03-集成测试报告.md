# **pytest 常见的两种报告格式**

在自动化测试工程中，建议先认识两种格式：JUnit XML 和 Allure Report。

## **① JUnit XML**

JUnit XML 是一种通用的测试结果交换格式。

pytest 可以直接生成：

```
pytest --junitxml=reports/junit.xml
```

执行后会产生：

```
reports/
└── junit.xml
```

这个 XML 文件记录了测试执行结果，包括测试用例数量、成功数量、失败数量、错误信息和执行时间等。

Jenkins 可以使用内置的 `junit` 步骤解析它：

```
post {
    always {
        junit 'reports/junit.xml'
    }
}
```

这样 Jenkins 就能在构建页面展示测试结果和趋势。

## **② Allure Report**

Allure 是专门用于自动化测试结果展示的报告框架。

它能够提供更加丰富的测试报告，包括：
- 测试用例执行统计、成功率和失败率。
- Feature、Story 等测试用例分类。
- 测试步骤及每个步骤的执行结果。
- 失败异常、错误堆栈和附件。
- 测试环境信息及历史趋势。

Allure 的优势在于，它不只是告诉你哪个测试失败了，还可以帮助你分析测试为什么失败。

```bash

pytest --alluredir=allure-results	
```

执行后，会在 allure-results 文件夹生成一些 JSON 文件，这些 JSON 文件就是 Allure 后续生成 HTML 报告所需要的原始数据。

## 第二步：生成并查看测试报告
工作原理中提到，`allure-pytest` 负责采集测试结果，`Allure CLI `负责生成 HTML 报告。

```baash
allure generate allure-results -o allure-report --clean
```

安装cli
```bash
# 去 https://github.com/allure-framework/allure2/releases 下载tgz包
# 假设下载的是 allure-2.x.x.tgz

sudo mkdir -p /opt/allure
sudo tar -xzf allure-2.x.x.tgz -C /opt/allure

# 将 CLI 加入 PATH

source ~/.bashrc

allure --version
```

生成测试报告

使用open，Allure 会启动本地 HTTP 服务，并尝试打开浏览器。
```
allure open allure-report
```

```
allure serve allure-results
```

# Allure 测试步骤与附件
学习三个功能：`@allure.step`、`allure.step()` 和 `allure.attach()`。

### `@allure.step`
```python
import allure

@allure.step("准备登录账号")
def prepare_account():
    username = "admin"
    password = "123456"

    return username, password
```

`@allure.step` 还支持字符串插值。
例如：
```python
@allure.step("使用账号 {username} 登录")
def login(username, password):    
	pass
```

## **allure.step()：动态添加测试步骤**

`@allure.step` 和 `allure.step()` 很相似，但使用场景不同。

前者主要用于装饰函数，后者通过上下文管理器定义步骤。

例如：

```python
import allure

def test_login():
    with allure.step("准备测试账号"):
        username = "admin"
        password = "123456"
    with allure.step("执行登录请求"):
        response = login(username, password)
    with allure.step("验证登录结果"):
        assert response.status_code == 200
```

这里使用了 Python 的 `with` 语法。

每个 `with allure.step()` 代码块都会形成一个独立的测试步骤。

### **两者的区别**

|对比|@allure.step|allure.step()|
|---|---|---|
|使用方式|装饰函数|with 上下文管理器|
|适用场景|封装的业务函数|当前测试函数中的临时步骤|
|是否可以嵌套|可以|可以|
|是否支持动态名称|支持|支持|

我的建议是：

对于项目中可以复用的业务操作，优先使用 `@allure.step`；对于某个测试函数内部临时组织的执行逻辑，使用 `with allure.step()`。

## **allure.attach()：添加测试附件**

这是本课非常重要的内容。

前面两个功能只能展示执行步骤，但如果测试失败，我们可能还需要查看：
- HTTP 请求参数。
- HTTP 响应内容。
- 接口请求头。
- 错误日志。
- 页面截图。
- 其他调试信息。

这些都可以通过 `allure.attach()` 添加到测试报告。

### **3.1 添加普通文本附件**

先看最简单的示例：

```python
import allure

def test_login():
    username = "admin"
    password = "123456"
    allure.attach(
        username,
        name="登录用户名",
        attachment_type=allure.attachment_type.TEXT
    )
    assert True
```

这里有三个重要参数：

|参数|作用|
|---|---|
|`body`|附件内容|
|`name`|附件名称|
|`attachment_type`|附件类型|

`allure.attachment_type.TEXT` 表示普通文本。

### **3.2 添加 JSON 请求响应附件**

对于 API 自动化测试，这个功能尤其有价值。

例如：

```python
import json
import allure


def test_login():
    request_data = {
        "username": "admin",
        "password": "123456"
    }
    response_data = {
        "code": 0,
        "message": "success",
        "token": "abcdef123456"
    }
    allure.attach(
        json.dumps(
            request_data,
            ensure_ascii=False,
            indent=4
        ),
        name="登录请求参数",
        attachment_type=allure.attachment_type.JSON
    )
    allure.attach(
        json.dumps(
            response_data,
            ensure_ascii=False,
            indent=4
        ),
        name="登录响应数据",
        attachment_type=allure.attachment_type.JSON
    )

    assert response_data["code"] == 0
```

这里使用了 Python 的 `json.dumps()`，把字典转换为格式化 JSON 字符串。

`ensure_ascii=False` 是为了避免中文被转换成 Unicode 编码。

### **3.3 添加日志附件**

假设测试执行过程中产生了一些调试日志：

```python
import allure

def test_login():
    log_content = """
    2026-11-23 10:00:00 INFO 开始登录
    2026-11-23 10:00:01 INFO 发送登录请求
    2026-11-23 10:00:02 ERROR 登录失败
    """
    allure.attach(
        log_content,
        name="登录执行日志",
        attachment_type=allure.attachment_type.TEXT
    )
    assert True
```

这样就可以把日志内容直接放在报告中，而不需要另外登录 Jenkins 服务器查看控制台输出。

实际工程中，更建议在发生失败时收集相关日志，避免报告附件过多。

### **3.4 添加截图附件**

Allure 也支持图片附件。

```python
import allure

def test_screenshot():
    screenshot = b"your image binary data"
    allure.attach(
        screenshot,
        name="页面截图",
        attachment_type=allure.attachment_type.PNG
    )
```

这里的 `screenshot` 应该是真正的图片二进制数据，示例中的字节占位符不能直接生成有效图片。

```python
import allure


@allure.epic("用户管理")
@allure.feature("用户登录")
@allure.story("正常登录")

            "code": 0,
            "message": "success",
            "token": "abcdef123456"
```

# **Allure Severity 与 pytest Fixture 集成**
前面已经学习了 Allure 的测试用例描述、业务分类、步骤和附件。本课继续完善测试报告，让报告能够体现用例的重要程度，并通过 pytest Fixture 自动收集测试过程中的信息，减少测试函数中的重复代码。

本课主要学习两个方面：使用 `@allure.severity` 标记用例优先级，以及结合 Fixture 和 pytest Hook 自动收集测试环境、失败信息和日志。

## **一、使用 Severity 标记用例重要程度**

在实际自动化测试中，不同用例的重要程度不同。例如，登录、支付等核心功能出现问题，通常比普通页面展示问题更加严重。

Allure 提供了 `@allure.severity` 装饰器，用于标记测试用例的严重程度。

```
import allure@allure.severity(allure.severity_level.CRITICAL)def test_user_login():    assert True
```

Allure 提供五个严重程度级别：

|级别|含义|典型场景|
|---|---|---|
|BLOCKER|阻断级|系统核心功能完全不可用|
|CRITICAL|严重|登录、支付等核心功能异常|
|NORMAL|普通|一般业务功能异常|
|MINOR|轻微|非核心功能存在问题|
|TRIVIAL|极轻微|文案、样式等细节问题|

这些级别本质上是测试报告中的元数据，不会自动改变 pytest 的执行结果，也不会直接决定 Jenkins 构建是否失败。

例如：

```
import allure@allure.epic("用户中心")@allure.feature("登录模块")@allure.story("用户登录")@allure.severity(allure.severity_level.CRITICAL)def test_login_success():    assert True@allure.epic("用户中心")@allure.feature("个人资料")@allure.story("修改昵称")@allure.severity(allure.severity_level.MINOR)def test_update_nickname():    assert True
```

生成报告后，可以在 Allure 报告中查看测试用例的 Severity 信息。

## **二、理解 pytest Fixture 在报告中的作用**

Fixture 是 pytest 的核心机制之一，用于管理测试用例执行前后的准备工作和资源清理。

例如，API 自动化测试通常需要创建客户端、准备测试数据、执行请求，最后关闭客户端。如果每个测试函数都重复编写这些逻辑，代码会越来越难维护。

可以通过 Fixture 统一管理：

```
import pytest@pytest.fixturedef api_client():    print("创建 API 客户端")    client = {        "base_url": "https://example.com"    }    yield client    print("关闭 API 客户端")
```

测试函数通过参数名使用 Fixture：

```
def test_get_user(api_client):    assert api_client["base_url"] == "https://example.com"
```

这里的 `yield` 是关键。pytest 执行 Fixture 时，先运行 `yield` 之前的代码，将对象交给测试函数；测试函数执行结束后，再继续执行 `yield` 之后的清理代码。

Fixture 本身并不会自动生成丰富的 Allure 报告内容，但可以在其中主动添加步骤和附件。

## **三、在 Fixture 中添加 Allure 步骤和附件**

例如，登录接口测试需要准备测试数据，可以把准备过程放在 Fixture 中，并使用 Allure 记录。

```
# conftest.pyimport pytestimport allure@pytest.fixturedef login_data():    with allure.step("准备登录测试数据"):        data = {            "username": "test_user",            "password": "******"        }        allure.attach(            data["username"],            name="测试用户名",            attachment_type=allure.attachment_type.TEXT        )    yield data    with allure.step("清理登录测试数据"):        print("执行测试数据清理")
```

测试文件：

```
# tests/test_login.pyimport allure@allure.title("用户登录成功")@allure.severity(allure.severity_level.CRITICAL)def test_login_success(login_data):    with allure.step("执行登录"):        assert login_data["username"] == "test_user"    with allure.step("验证登录结果"):        assert True
```

这样，Fixture 负责准备和清理，测试函数负责业务验证，Allure 则负责记录测试过程。

需要注意，真实项目中不要把密码、Token、Cookie 或 Authorization 等敏感信息直接写入附件。即使是测试环境，也建议进行脱敏处理。

## **四、使用 pytest Hook 自动收集失败信息**

上面的方式需要在每个 Fixture 或测试函数中主动添加附件。如果项目中有大量测试用例，可以进一步使用 pytest Hook，在测试失败时自动收集失败信息。

pytest 提供了 `pytest_runtest_makereport` Hook，可以获取测试用例不同阶段的执行结果。

在项目根目录的 `conftest.py` 中添加：

```
import pytestimport allure@pytest.hookimpl(hookwrapper=True)def pytest_runtest_makereport(item, call):    outcome = yield    report = outcome.get_result()    # 只处理测试函数执行阶段的失败    if report.when == "call" and report.failed:        allure.attach(            str(report.longrepr),            name="pytest 失败信息",            attachment_type=allure.attachment_type.TEXT        )
```

这里有几个重要概念：

`pytest_runtest_makereport`：pytest 在测试执行的不同阶段生成测试报告时调用的 Hook。

`hookwrapper=True`：允许 Hook 在 pytest 原有处理逻辑执行前后进行操作。

`yield`：等待 pytest 完成原有处理逻辑。

`report.when == "call"`：表示当前处理的是测试函数执行阶段，而不是 Fixture 初始化或清理阶段。

`report.failed`：表示当前阶段执行失败。

这个示例只处理测试函数执行阶段的失败。如果需要收集 Fixture 初始化失败或清理失败的信息，还需要分别处理 `setup` 和 `teardown` 阶段。

## **五、配置 Allure Environment 环境信息**

除了测试步骤和失败信息，报告还可以展示本次测试运行的环境信息，例如 Python 版本、测试环境、操作系统等。

Allure 2 支持通过 `environment.properties` 文件展示环境信息。

例如，在 `allure-results` 目录中创建：

```
Environment=Test
PythonVersion=3.12
OperatingSystem=Ubuntu
TestFramework=pytest
```

目录结构如下：

```
project/
├── tests/
├── allure-results/
│   ├── environment.properties
│   └── ...
├── conftest.py
└── pytest.ini
```

生成报告时，Allure 会读取该文件，并在报告的 Environment 区域展示这些属性。

这里要区分两个概念：`allure.dynamic.label()` 用于给当前测试用例添加标签；`environment.properties` 用于展示本次测试运行的环境信息，两者用途不同。

## **六、区分 pytest Marker 与 Allure Severity**

这两个概念容易混淆，但它们解决的是不同问题。

`@allure.severity` 用于标记测试用例的重要程度，主要服务于 Allure 报告。

`@pytest.mark` 用于给测试用例添加标记，可以配合 pytest 命令筛选实际执行的用例。

例如，在 `pytest.ini` 中注册 Marker：

```
[pytest]
markers =
    smoke: 冒烟测试
    regression: 回归测试
```

在测试用例中使用：

```
import pytestimport allure@pytest.mark.smoke@allure.severity(allure.severity_level.CRITICAL)def test_login():    assert True@pytest.mark.regression@allure.severity(allure.severity_level.NORMAL)def test_update_user_info():    assert True
```

执行冒烟测试：

```
pytest -m smoke
```

执行回归测试：

```
pytest -m regression
```

两者可以同时使用。例如，一个测试用例既可以属于 `smoke`，也可以具有 `CRITICAL` 的严重程度。

## **七、与 Jenkins Pipeline 集成**

你目前已经能够在 Jenkins 中生成和查看 Allure 报告，因此本课不需要修改原有 Pipeline 的整体结构。

继续使用原来的 pytest 命令：

```
pytest --alluredir=allure-results --clean-alluredir
```

Jenkins Pipeline 中保留：

```
post {
```

这样，无论测试成功还是失败，Jenkins 都会尝试生成 Allure 报告。新增的 Severity、Fixture 附件和失败信息会随着本次测试结果一起进入报告。
