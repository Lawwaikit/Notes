# 数据库事务 的四个特性 ACID
1. **原子性**（Atomicity）
	指事务包含的所有操作要么全部成功，要么全部失败回滚。这意味着事务内的操作如果失败，会回滚到事务开始前的状态；如果成功，则事务内的所有操作都会提交。原子性确保事务内的操作要么全做，要么全不做，是一个不可分割的工作单位。这是数据库事务最基本的特性之一，保证了数据的完整性和一致性。

2. **一致性**（Consistency）
	指事务必须使数据库从一个一致性状态变换到另一个一致性状态。也就是说，一个事务执行之前和执行之后都必须处于一致性状态。一致性与业务有关，因此，对一致性的理解需要依赖特定的业务逻辑。在数据库操作中，一致性通过约束、触发器、存储过程和数据库规则等来实现。例如，银行转账业务中，两个账户的总金额在事务前后应该保持一致。

3. **隔离性**（Isolation）
	指并发的事务是相互隔离的。即一个事务内部的操作及正在操作的数据必须封锁起来，不被其它企图进行修改的事务看到。隔离性通过锁机制来实现，确保并发执行的事务不会互相干扰。如果没有隔离性，多个事务同时对同一数据进行操作，可能会导致数据不一致的问题，如脏读、不可重复读和幻读等。

4. **持久性**（Durability）
	指一旦事务提交，则其结果就是永久的。即使系统发生崩溃或者故障，数据库也能将数据恢复到事务成功结束时的状态。持久性通过数据库的备份、恢复和日志机制来保证。例如，在关系数据库中，一旦事务提交，其对数据的修改就会被永久地保存在数据库中。即使系统出现故障，数据库也可以通过日志进行恢复，确保数据的完整性和一致性。

# 数据库的隔离级别 **isolation**

1. 类型一：读未提交（Read Uncommitted）
	可以读取到事务未提交的数据，隔离性差，会出现 **脏读（当前内存读），不可重复读，幻读**问题;

2. 类型二：读已提交（Read Committed）
	可以读取到事务已提交的数据，隔离性一般，**不会出现脏读**问题，但是**会出现不可重复读，幻读**问题；

3. 类型三：可重复读（Repeatable Read）**MySQL默认**
	**可以防止脏读**（当前内存读），**防止不可重复读**问题，**防止会出现的幻读**问题，但是并发能力较差；
	会使用next lock锁进制，来防止幻读问题，但是引入锁进制后，锁的代价会比较高，比较耗费CPU资源，占用系统性能；

4. 类型四：串行化（Serializable）
	隔离性比较高，可以实现串行化读取数据，但是事务的并发度就没有了；
	这是事务的最高级别，在每条读的数据上，加上锁，使之不可能相互冲突

# 三种并发问题是什么？

假设账户余额初始为 100 元，事务 A 和事务 B 同时操作数据库。

### 1. 脏读（Dirty Read）

**事务 A** 修改余额为 200 元，但还没有提交。此时**事务 B** 查询余额，读到了 200 元；随后**事务 A** 回滚，余额恢复为 100 元。

**事务 B** 读取了一个最终没有生效的数据，这就是脏读。读未提交允许脏读，其余三个隔离级别不允许。

**事务B读取了其他事务未生效的数据**
### 2. 不可重复读（Non-repeatable Read）

**事务 A** 第一次查询余额，得到 100 元。
随后**事务 B** 将余额修改为 200 元并提交，**事务 A** 再次查询时，得到 200 元。

**同一个事务中，两次读取同一条记录，结果不一致**，这就是不可重复读。读已提交可能出现这种情况，而可重复读通过一致性读视图等机制保证普通快照读的一致性。

### 3. 幻读（Phantom Read）

假设**事务 A** 执行查询：

```sql
SELECT * FROM users WHERE age >= 18;
```

第一次查询得到 10 条记录。

随后**事务 B** 插入一条 `age = 20` 的用户记录并提交，事务 A 再次执行相同查询时，可能得到 11 条记录。

新增的记录就像突然出现的幻影，因此称为幻读。
它与不可重复读的区别是，不可重复读主要关注已有记录的内容发生变化，幻读主要关注**符合查询条件的记录集合发生变化**。
